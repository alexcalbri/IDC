# Clientes Module

Status: locked base module scaffold.

Clientes exposes the shared IdeasCore Customer/Prospect identity to the UI and
other modules. Because every company needs the customer surface, new tenant
databases install this module automatically and seed it as enabled in
`tenant_modules`.

The customer schema is owned by this module and lives in:

```text
modules/clientes/migrations/V001__create_customers.sql
```

Implemented baseline:

- `GET /modules/clientes/customers` lists customers for users with
  `clientes.view`.
- `POST /modules/clientes/customers` creates customers for users with
  `clientes.create`.
- Creating a customer requires only Nombre; Correo and Telefono are optional.
  Since migration V005 the database accepts an empty email or phone (stored as
  `''`, never NULL), so modules such as CRM can register a person known only
  by name and one contact channel.
- Every customer has a `customer_code` (migration V004): 8 random characters
  without look-alikes (no 0/O, 1/I), unique per company and generated by the
  database on insert, including for customers that existed before. It is
  read-only and shown in the customer list; modules such as Hotspot use it to
  identify the customer (e.g. WiFi access by code).
- Extra Customer/Core fields created from the Clientes administration surface
  are backed by `customer_field_definitions` and stored in
  `customers.flexible_attributes`.
- Module-specific fields must be stored by the owning module, not in the shared
  Clientes field table, unless they are intentionally promoted to the shared
  customer record.

## AI agent tools

With the `agentes` module, agents can use (`ClientesMcpTools.kt`), with the same permissions and
validations as the routes:

| Tool | Permission | Does |
|---|---|---|
| `clientes_search_customers`, `clientes_get_customer`, `clientes_list_customer_fields` | `clientes.view` | Search customers, read one by id or code, list the custom fields. |
| `clientes_create_customer` | `clientes.create` | Creates a customer (name required, no duplicated email). |
| `clientes_update_customer` | `clientes.edit` | Changes only the data sent. |
| `clientes_archive_customer` | `clientes.delete` | Archives a customer, like `DELETE /customers/{id}`. |
| `clientes_get_customer_history` | `clientes.view` | The customer's history, like `GET /customers/{id}/history`. |
| `clientes_create_customer_field` | `clientes.fields.manage` | Adds a custom field, like `POST /fields`. |

## Customer history

`GET /modules/clientes/customers/{id}/history` (`clientes.view`) returns what happened with a
customer, newest first: who created, edited (field by field, before and after) or archived it in
Clientes (`customer_activity`), plus what every installed module reports through its
`CustomerTimeline` (CRM leads, reservations, sales and notes; hotspot WiFi connections...). Each
module's entries appear only when it is enabled and the user holds its permission. Clientes knows no
module: see "Customer history" in `modules/README.md`.
